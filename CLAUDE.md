# ENCY Localizer — ориентир для Claude

Прототип веб-локализатора ENCY / Tuner для Руслана (продуктовый дизайнер ENCY). Статический сайт без сборки и зависимостей, собран на дизайн-системе **ENCY Core** (скилл `ency-core-design`). Живёт на https://marda6.github.io/Localisator/ (репо `Marda6/Localisator`, ветка `main`).

## Что это и для кого

Задача сайта одна: быстро переводить строки интерфейса с английского эталона на другие языки. Всё остальное (прогресс, администрирование, руководство) второстепенно. ТЗ и отзывы тестировщиков — в README и в разделе «Руководство» на сайте. Ключевые требования из ТЗ: 28 приложений, четыре статуса (Translated / Outdated / Not translated / Autotranslated), проверки `%s` и переносов, запрет контактов дилеров, автоперевод, процент по языкам и приложениям, экспорт `.lng`, поиск по ключу, доступ дилеров many-to-many, копирование и перенос версий 17.0 → 18.0.

## Файлы

- `dist/index.html` — оболочка. `dist/app.js` — весь UI (шаблонные строки, один `render()`), `dist/styles.css` — стили на токенах Core, `dist/data.js` — демо-корпус и генератор состояний, `dist/core.js` — чистая логика (валидация, статистика, экспорт, миграция). `dist/assets/fonts` — Inter.
- `tests/core.test.js` — 7 тестов на core и каталог. Гоняются в CI.
- `localisator.html` — автономная сборка, собирается `node build_standalone.mjs`. Всегда пересобирать перед коммитом.
- `index.html` в корне и `.nojekyll` — редирект на `dist/`, чтобы Pages в режиме «из ветки» открывал приложение, а не README.
- `start_local.mjs` — локальный сервер (`npm start`, порт 8080). Python-скрипты оставлены для тех, у кого он есть; на машине Руслана Python нет.
- `.claude/launch.json` — конфиг превью (Node). `.github/workflows/pages.yml` — деплой через Actions; в режиме Pages «из ветки» он падает на configure-pages, это не влияет на сайт.

## Рабочий цикл

```bash
npm run check && npm test && node build_standalone.mjs
git add -A && git commit -m "..." && git push origin main
```

Руслан обычно держит `npm start` на 8080. Для скриншотов использую headless Chrome на порту 8081:
`node start_local.mjs --port 8081 &` → `chrome --headless=new --screenshot=... http://127.0.0.1:8081/#progress` → убить процесс на 8081 через `netstat`/`taskkill`. Превью через `preview_start` в сессии может блокироваться классификатором; headless Chrome работает всегда.

Правки в `app.js` удобнее делать маленьким Node-скриптом `_p.mjs` с точными `replace` (bash-heредок ломает бэкслэши в шаблонных строках), потом удалить скрипт. CSS дописываю блоками `/* v2.N: ... */` в конец `styles.css`; каскад намеренно перебивает ранние правила.

## Устройство интерфейса

Шапка 48px: бренд, Mode tabs (Переводы / Прогресс / Администрирование), версия, язык, иконки руководства, темы и роли.

**Переводы** — три панели с перетаскиваемыми разделителями (`.gutter`, ширины в `db.layout`):
- Дерево приложений: карточки `.arow` (имя, %, полоса, сводка «N без перевода · N авто · N устарело»). Цвет только у выбранной/наведённой, остальные в сером, но заголовки яркие.
- Список строк: шапка = название + поиск; тулбар = чипы статусов (сворачиваются до точки при ширине < 760px через container query) + модуль + «Мои»; подвал = счётчик, Ignored-тумблер, «Автоперевод», «Скачать .lng». Три колонки: English / перевод / статус.
- Инспектор: эталон (14px), поле перевода (14px, ~132px), проверки одной строкой, вкладки Контекст / Совпадения / История (28px сегменты). Совпадения — карточки с чекбоксами, «Применить к N» и кнопка «И ещё N» в подвале; выбор в `S.matchSel`. История — таймлайн с «Вернуть этот вариант». Ignored — иконка-глаз в шапке инспектора, только админу. «Применить» = применить и перейти к следующей.

**Прогресс** — слева вертикальные карточки языков (клик выбирает язык), справа тепловая карта приложение × язык: пять дискретных ступеней (коралл 0–24, янтарь 25–49, жёлто-зелёный 50–74, светло-зелёный 75–99, зелёный 100), легенда кликабельна и фильтрует ячейки, группы сворачиваются, ширина первых трёх колонок регулируется (`.colgrip`), сортировка «по группам / сначала отстающие».

**Администрирование** — центрированная страница: компании и доступ к языкам (чекбоксы в таблице), языки, приложения, копирование/перенос, исключаемые модули.

## Решения по дизайну, которые Руслан утвердил

- Плотность Core: строки 24px, шрифт 12px, радиусы 4/8/12, только токены.
- Меньше интерфейса: ответственный и модуль не в таблице, а в контексте строки. Ignored не в списке статусов.
- Чекбоксы монохромные (fg-96 с тёмной галочкой), не зелёные.
- Разделители и осмысленные ряды вместо `flex-wrap`, который рвал тулбар.
- Цвет как указатель: окрашено только выбранное.
- Технические имена приложений (CAM_CAD, XMLCONFIG) показываются отдельно от читаемых названий; в карте — отдельной колонкой.

## Известные ограничения

- Иконки — временные контурные глифы; Figma MCP в сессиях не авторизован. При подключении заменить на SVG из наборов `icn_inspector` / `Filters icons` файла Core и обновить `components.md` скилла.
- Демо-данные генерируются `maturity(app, lang)` в `data.js` для разброса на карте; реальных строк нет.
- Черновики перевода живут только в сессии (`drafts`), в localStorage сохраняются применённые переводы и настройки (`ency-localizer-v2`).
